1. Introduction

1.1 Purpose

The ESP Network Protocol (ENP) is a lightweight networking protocol designed for ESP32 devices.

ENP provides a transport-independent communication layer for embedded systems by abstracting the underlying radio technology.

The first implementation of ENP uses ESP-NOW as its transport layer.

Future transports may include:

Wi-Fi
Ethernet
BLE
LoRa
Serial

without requiring changes to the application layer.

1.2 Design Goals

ENP is designed with the following objectives:

Lightweight
Deterministic
Low memory footprint
Transport independent
Modular
Mesh capable
Reliable
Easy to debug

1.3 Non-Goals

ENP is not intended to:

Replace TCP/IP
Compete with Thread
Compete with ZigBee
Replace MQTT

ENP is designed specifically for ESP32 embedded networks.

3. Node Model

Every ENP device is a node.

A node MUST possess:

unique Node ID
MAC address
role
protocol version

3.1 Node Roles

typedef enum
{
    ENP_ROLE_UNKNOWN = 0,

    ENP_ROLE_GATEWAY,

    ENP_ROLE_SENSOR,

    ENP_ROLE_RELAY,

    ENP_ROLE_ROOT,

    ENP_ROLE_MONITOR

} enp_role_t;

Additional roles MAY be defined in future versions.

4. Node Identity

ENP distinguishes between physical identity and logical identity.

Physical Identity -> ESP32 MAC Address
Used only by the transport layer.

Logical Identity -> 32-bit Node ID
Used by ENP.

Applications MUST use Node IDs instead of MAC addresses whenever possible.

5. Packet Format

Every ENP packet begins with a common header.

typedef struct __attribute__((packed))
{
    uint8_t version;

    uint8_t type;

    uint16_t length;

    uint32_t sequence;

    uint32_t source;

    uint32_t destination;

    uint8_t ttl;

    uint8_t flags;

    uint16_t crc;

} enp_header_t;

All multi-byte values SHALL be transmitted in little-endian format.

6. Packet Types

typedef enum
{
    ENP_DISCOVERY = 1,

    ENP_DISCOVERY_REPLY,

    ENP_SENSOR_DATA,

    ENP_ACK,

    ENP_HEARTBEAT,

    ENP_ROUTE_REQUEST,

    ENP_ROUTE_REPLY,

    ENP_MANAGEMENT,

    ENP_OTA

} enp_packet_type_t;

Future packet types MUST remain backward compatible.

7. Packet Flags

typedef enum
{
    ENP_FLAG_NONE            = 0x00,

    ENP_FLAG_ACK_REQUIRED    = 0x01,

    ENP_FLAG_BROADCAST       = 0x02,

    ENP_FLAG_RETRANSMISSION  = 0x04,

    ENP_FLAG_ENCRYPTED       = 0x08

} enp_flags_t;

Flags MAY be combined.

8. Discovery

Discovery enables nodes to locate gateways without prior configuration.

Sensor:

BOOT

↓

Broadcast DISCOVERY

↓

Wait

Gateway:

Receive DISCOVERY

↓

DISCOVERY_REPLY

↓

Sensor receives

↓

Store Gateway

↓

Ready

No MAC addresses shall be configured manually.

9. Reliability

ENP provides optional reliable delivery.

If ACK_REQUIRED is set:

Transmit

↓

Wait ACK

↓

Timeout

↓

Retry

↓

Failure

Maximum retry count is implementation defined.

10. Sequence Numbers

Every packet SHALL contain a monotonically increasing sequence number.

Sequence numbers SHALL wrap after 2^32−1.

11. Time To Live

TTL prevents routing loops.

Default:

TTL = 16

Every forwarding node MUST decrement TTL.

Packets reaching TTL = 0 SHALL be discarded.

12. Duplicate Suppression

Each node SHALL maintain a cache containing:

Source Node ID + Sequence Number

Duplicate packets SHALL be discarded.

13. Heartbeat

Every node SHOULD transmit a heartbeat every 10 seconds.

Heartbeat contains:

Node ID
Role
Firmware Version
Protocol Version
RSSI
Battery (optional)

14. Neighbor Table

Each node SHOULD maintain:

Node ID
MAC
RSSI
Role
Hop Count
Last Seen

15. Routing Table

Routing entries contain:

Destination
Next Hop
Metric
Age

Routing algorithms are outside the scope of version 0.2.

16. Statistics

Each node SHALL maintain statistics.

Minimum counters:

TX Packets
RX Packets
Sensor Packets
ACK Packets
CRC Errors
Send Errors
Duplicates
Forwarded
Dropped

17. Versioning

Protocol Version

Major.Minor.Patch

Breaking protocol changes SHALL increment Major.

Backward compatible additions SHALL increment Minor.

Bug fixes SHALL increment Patch.

18. Security

Version 0.2 does not define encryption.

Future versions MAY support:

AES-128
Session keys
Secure discovery
