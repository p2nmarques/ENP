# E3.3.7 Phase 4 / P4-E4D — Production Runtime Hardware Validation

**Status:** HARDWARE VALIDATED / FROZEN  
**Target:** ESP-IDF 6.0.2  
**Validation date:** 2026-08-17  
**Validation type:** Real-hardware, real ESP-NOW production-path validation

---

## 1. Purpose

P4-E4D validates the P4-E4C production runtime composition on real ESP32
hardware using the real ESP-NOW transport and the production receive/routing
path.

The objective is to establish hardware-validation evidence for the production
runtime wiring without changing the established ENP interfaces.

---

## 2. Hardware configuration

Two real ESP32 nodes were used:

| Node | Role | ENP node |
|---|---|---:|
| Node 1 | Gateway | 1 |
| Node 2 | Sensor | 2 |

Both nodes operated on Wi-Fi channel 10 with ESP-NOW 2.0.

---

## 3. Production path validated

The test exercised:

```text
Real ESP-NOW
    ↓
Production transport RX
    ↓
Production receive path
    ↓
    ├── DATA / ACK → data plane / routing
    │
    └── other ENP traffic → dispatcher
    ↓
Application/service
```

The production runtime composition included:

```text
ENP context
Dispatcher
Discovery service
Routing data path
Production receive path
ESP-NOW transport
Maintenance
```

---

## 4. Gateway evidence

P4-E4D Gateway evidence (2026-08-17):
- ESP-IDF 6.0.2; hardware role GATEWAY / NODE 1.
- Wi-Fi connected on channel 10.
- ESP-NOW 2.0 initialized.
- Production ENP context, dispatcher, Discovery/DATA/ACK services, routing data path,
  production receive path and maintenance initialized.
- Discovery populated the Sensor transport address and installed the production route.
- DATA was submitted through the production routing path to ESP-NOW.
- Real ESP-NOW ACK reached the local application service.
- Production receive path delivered the correlated ACK.
- Test ended with: E3.3.7 Phase 4 / P4-E4D hardware validation PASS.


The Gateway log specifically records production receive-path delivery of the
correlated ACK after DATA was submitted through the production routing path.

---

## 5. Sensor evidence

P4-E4D Sensor evidence (2026-08-17):
- ESP-IDF 6.0.2; hardware role SENSOR / NODE 2.
- Wi-Fi connected on channel 10.
- ESP-NOW 2.0 initialized.
- Production ENP context, dispatcher, Discovery/DATA/ACK services, routing data path,
  production receive path and maintenance initialized.
- Real ESP-NOW DATA reached the local application service.
- Correlated ACK transmitted through real ESP-NOW.
- Real DATA reached the Sensor application exactly once.
- Test ended with: E3.3.7 Phase 4 / P4-E4D hardware validation PASS.


The Sensor log specifically records real ESP-NOW DATA reception, correlated
ACK transmission and exactly-once DATA delivery to the Sensor application.
