## 1. Purpose

I33 validates the end-to-end Reliability recovery path across the already-frozen
E5D Step-3 route-repair implementation.

The test does not modify P4-E5B, P4-E5C, P4-E5D Step-3, R4, routing, transport,
or the Reliability production implementation.

## 3. Hardware result

The final hardware run satisfied the complete acceptance path:

- initial correlation `C1 = 0x00000001`;
- real transport failure with B as failed next hop;
- exactly one E5E repair request;
- valid repair ID;
- Reliability entered `REPAIR_PENDING`;
- retry budget remained unchanged during repair;
- one real RREQ was submitted through the observed transport;
- RREQ synchronous submission did not fail;
- successful RREP was received from C;
- repaired route became ACTIVE using C as next hop;
- repair completion was accepted;
- post-repair correlation `C2 = 0x00000002`;
- no unexplained additional correlation allocation;
- Reliability returned to `WAITING_FOR_ACK`;
- exactly one normal retransmission occurred;
- retry count increased exactly once;
- final I33 hardware validation reported `PASS`.

## 4. Correlation policy

I33 treats:

```text
C1 = initial DATA attempt
C2 = legitimate post-repair retransmission
```

as the only expected correlation allocations.

Any unexplained allocation before repair, during repair, or after C2 is a
validation failure.

## 5. Repair and retry policy

During `REPAIR_PENDING` the Reliability transaction remains the same transaction
and the retry count must not increase. Route repair may complete without
consuming the normal retry budget.

After successful repair, the repaired route is independently verified, the same
Reliability transaction resumes, one normal retransmission is expected, and the
retry count increases exactly once.

## 6. Node B disconnect

Node B is intentionally powered off to create the failed-next-hop condition.

Its serial-console message:

```text
GetOverlappedResult failed
PermissionError(13, 'Access is denied')
Waiting for the device to reconnect
```

is **expected test behavior**, not an I33 failure.
