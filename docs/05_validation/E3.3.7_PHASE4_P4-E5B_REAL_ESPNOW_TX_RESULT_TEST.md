# E3.3.7 Phase 4 / P4-E5B — Real ESP-NOW TX-Result Observation

**Status:** HARDWARE VALIDATED / FROZEN (2026-08-18)  
**Target:** ESP-IDF 6.0.2

## Purpose

Validate the frozen P4-E5A send-result observation boundary using the real
ESP-NOW transport on an ESP32.

## Test condition

The test sends a unicast frame to the configured:

```text
02:00:00:E5:0B:5B
```

This address must not be an active ESP-NOW peer during the test. Change the
macro in the test source if that address is used in the test environment.

Expected behavior:

```text
enp_transport_send()
        ↓
esp_now_send() returns ESP_OK
        ↓
real ESP-NOW send callback
        ↓
ESP_NOW_SEND_FAIL
        ↓
bounded static queue
        ↓
ENP ESP-NOW worker task
        ↓
enp_transport_send_result_callback_t
        ↓
non-ESP_OK result
```

## Acceptance criteria

The hardware test passes only when all of the following are observed:

1. Wi-Fi is connected.
2. The real ESP-NOW transport initializes.
3. The production send-result callback registers successfully.
4. The real unicast transmission is accepted asynchronously by
   `esp_now_send()`.
5. Exactly one real TX-result callback is observed.
6. The callback reports a non-`ESP_OK` result.
7. The callback preserves the configured destination address.
8. The callback executes through the ENP transport worker task rather than
   requiring routing work in the ESP-NOW callback.
9. The real transport deinitializes cleanly.

## Deliberate exclusions

P4-E5B does not test or modify:

- route invalidation;
- RERR;
- RREQ/RREP;
- route discovery;
- route repair;
- reliability.

Those remain later Phase 4 boundaries.
