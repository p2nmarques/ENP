# E3.3.7 Phase 4 / P4.1 — Reusable ENP Data Plane

**Target:** ESP-IDF 6.0.2  
**Status:** Implementation complete — hardware-independent self-test pending  
**Scope:** Reusable receive data-plane and DATA/ACK duplicate-domain ownership

## 1. Purpose

P4/E1 begins Phase 4 consolidation of the behavior proven by E1, E2 and E3.
The objective is to move receive-time DATA/ACK forwarding and duplicate
suppression out of the E3C integration application and into reusable ENP core
infrastructure.

P4/E1 deliberately does **not** consolidate cached-ACK recovery or route repair.
Those remain subsequent Phase 4 work items.

## 2. New reusable component

```text
core/data/
    enp_data_plane.h
    enp_data_plane.c
```

The data plane owns:

- complete ENP packet validation;
- DATA duplicate suppression;
- ACK duplicate suppression;
- local-vs-remote destination classification;
- forwarding of non-local DATA and ACK packets through
  `enp_routing_data_path_forward()`;
- optional local packet delivery through a transport-independent callback.

No dynamic allocation is introduced.

## 3. Duplicate domains

The E3C test demonstrated that DATA and ACK duplicate identities must remain
separate. P4/E1 moves that ownership into `enp_data_plane_t`:

```text
ENP data plane
    |
    +-- DATA duplicate cache
    |
    +-- ACK duplicate cache
```

Both caches continue to use the same identity rule:

```text
source logical address + sequence
```

A DATA packet and an ACK packet carrying the same source/sequence pair are
therefore independently eligible for processing.

## 4. Routing boundary

The data plane does not implement routing decisions. It calls the existing:

```c
enp_routing_data_path_forward()
```

for non-local DATA/ACK packets.

The existing routing path remains responsible for:

- active route lookup;
- next-hop selection;
- logical-to-transport resolution;
- TTL decrement;
- CRC resealing;
- transport transmission.

This preserves the E1 routing boundary.

## 5. Dispatcher boundary

The existing `enp_dispatcher_dispatch()` API remains available for existing
callers and historical tests.

P4/E1 adds:

```c
enp_dispatcher_dispatch_local()
```

which validates and dispatches a packet without consulting the dispatcher's
legacy packet-wide duplicate cache.

This allows a future production receive path to use:

```text
Transport
    ↓
ENP data plane
    ↓
DATA/ACK domain duplicate suppression
    ↓
local packet → dispatcher_local
remote DATA/ACK → routing forward
```

without applying duplicate suppression twice.

## 6. P4/E1 self-test

Test source:

```text
main/tests/2-E/E3.3.7_p4_E1_test_enp_data_plane_main.c
```

The self-test validates:

1. data-plane initialization;
2. DATA forwarding through the existing routing path;
3. next-hop selection;
4. TTL decrement;
5. preservation of the caller's packet;
6. duplicate DATA suppression;
7. ACK forwarding with the same source/sequence identity as DATA;
8. independent ACK duplicate suppression;
9. one identity in each duplicate domain;
10. clean data-plane deinitialization.

## 7. Not included in P4/E1

The following remain outside this step:

- cached ACK storage and recovery;
- reliability transaction scheduling;
- periodic reliability tick ownership;
- RERR processing integration;
- route repair;
- route rediscovery after next-hop failure;
- three-node hardware validation using the consolidated data plane.

Those will be handled incrementally in later Phase 4 steps.
