# E3.3.7 Phase 4 / E2 — Reliability Runtime Integration

**Project:** ENP v0.2-r5  
**Target:** ESP-IDF 6.0.2  
**Status:** Implementation prepared; hardware-independent self-test pending

## Purpose

P4/E2 moves periodic reliability servicing from test/application code into the existing ENP maintenance scheduler.

The reliability layer remains transport-independent and FreeRTOS-independent. `enp_maintenance` is the runtime scheduler responsible for invoking `enp_reliability_tick()` periodically.

## Smallest integration extension

No new reliability API is required.

The existing APIs are sufficient:

```text
enp_reliability_send()
enp_reliability_process_ack()
enp_reliability_tick()
```

The existing `enp_maintenance` task already provides a static FreeRTOS task and periodic maintenance cycle. The smallest integration is therefore:

```text
ENP maintenance task
        |
        +-- enp_reliability_tick(now_ms)
        +-- neighbor aging
        +-- periodic discovery
```

The reliability implementation itself contains no FreeRTOS dependency.

## Runtime boundary

```text
Reliability
    |
    | enp_reliability_tick(now_ms)
    v
ENP Maintenance Scheduler
    |
    +-- StaticTask
    +-- periodic timing
    +-- neighbor aging
    +-- discovery
```

Reliability still owns:

- transaction state;
- retry counters;
- timeout deadlines;
- retransmission packet copies;
- ACK correlation;
- completion results.

Maintenance owns only the scheduling of `enp_reliability_tick()`.

## P4/E2 self-test

`E3.3.7_p4_E2_test_enp_reliability_maintenance_main.c` is hardware-independent and uses a controlled static transport.

It verifies:

1. ENP context initialization;
2. reliability initialization/start;
3. maintenance task startup;
4. initial reliable DATA submission;
5. maintenance-driven timeout processing;
6. exactly one retransmission after the reliability timeout;
7. preservation of the complete DATA transaction identity;
8. ACK completion of the transaction;
9. clean maintenance stop request;
10. clean reliability/context/transport deinitialization.

The current baseline uses a 1000 ms reliability ACK timeout and a 2000 ms maintenance interval. Therefore the self-test waits through the first maintenance cycle to observe the retry.

## Non-goals

P4/E2 does not change:

- route lookup;
- route forwarding;
- RREQ/RREP/RERR;
- transport implementations;
- duplicate suppression;
- ACK forwarding;
- route repair;
- reliability transaction semantics.

## Acceptance criterion

The self-test is accepted when the maintenance task causes the reliability transaction to retransmit exactly once and the same transaction is subsequently completed by its correlated ACK.
