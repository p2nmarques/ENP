**Status:** AUDIT RESOLVED / IMPLEMENTATION GATE STILL CLOSED

## Correction to the earlier audit

The earlier draft `E3.3.7_RERR_INTEGRATION_AUDIT_GATE.md` incorrectly described an
alternative reason-code table as the "canonical protocol specification".

The provenance review found no authoritative baseline document supporting that
alternative table.

The earlier statement is therefore a **documentation-audit error**, not evidence
of a production protocol mismatch.

## Authoritative contract

The authoritative contract is the canonical routing wire definition:

```text
0 = UNKNOWN
1 = NO_ROUTE
2 = NEXT_HOP_UNREACHABLE
3 = ROUTE_EXPIRED
4 = LOCAL_REPAIR_FAILED
5 = TTL_EXPIRED
```

Only values 1..5 are valid RERR reasons.

## Audit findings retained

The following findings remain valid:

- RERR wire format is 16 bytes.
- `enp_routing.h/.c` is the canonical wire source.
- R4-D owns validation, applicability, sequence freshness and route invalidation
  through callbacks.
- R4-D does not own transport, Reliability or persistent route-table storage.
- Route invalidation transitions the affected route to STALE.
- R4-D tests cover freshness, wrap-around, malformed input, valid reasons and
  wire round-trip.
- E1.3 covers newer-RERR invalidation, stale-RERR protection, unknown sequence
  against a known route, and absent-route handling.
- E1.3 remains an RERR sub-gate and does not constitute complete E1 acceptance.

## Implementation gate

The reason-code contract is no longer a blocker.

However, this audit does **not** authorize production RERR changes. The next
RERR implementation gate must still be defined and approved separately.
