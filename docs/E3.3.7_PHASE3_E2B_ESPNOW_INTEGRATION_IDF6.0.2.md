# E3.3.7 Phase 3 / E2-B — Real ESP-NOW Integration

**Project:** ENP v0.2-r5  
**Target:** ESP-IDF 6.0.2  
**Status:** Implementation prepared; two-node hardware validation pending

## Purpose

E2-B connects the validated E2-A context/neighbor integration and E1 routing
DATA path to the existing ESP-NOW transport implementation.

The test uses two physical ENP nodes:

```text
Node 1 / sender  --->  Node 2 / receiver
```

Node 1 uses:

- real `enp_context_t`;
- real neighbor table;
- real logical-to-transport neighbor mapping;
- real route table;
- real `enp_routing_data_path`;
- real `enp_transport_t`;
- real ESP-NOW transport.

Node 2 uses the real ENP context and ESP-NOW transport receive callback to
validate the serialized ENP frame.

## Boundary

```text
ENP logical destination
        |
        v
route table
        |
        v
logical next hop
        |
        v
real neighbor table
        |
        v
ESP-NOW MAC
        |
        v
enp_transport_send()
        |
        v
ESP-NOW
        |
        v
Node 2 receive callback
```

The ESP-NOW MAC is used only as the transport address. It is not used as the
ENP node identifier.

## Deliberate scope

E2-B does not add routing discovery, RREQ/RREP/RERR processing, reliability,
ACK generation, forwarding, or duplicate suppression.

It verifies only the real origin DATA submission path.

## Test configuration

Node 2 prints its STA MAC at startup. Before flashing Node 1, set the six
`E2B_PEER_MAC_*` constants in the E2-B test source to Node 2's STA MAC.

Set `CONFIG_ENP_E3_NODE_ID=1` for Node 1 and `CONFIG_ENP_E3_NODE_ID=2` for
Node 2.

The MAC values are test configuration only and must not become part of the
ENP logical addressing model.

## Acceptance criteria

### Node 1

- Wi-Fi initialized and connected.
- Real ESP-NOW transport initialized through `enp_context`.
- Real neighbor table contains logical Node 2 -> Node 2 STA MAC.
- Active route Node 2 -> next hop Node 2 exists.
- Routing data path uses the real context resolver.
- DATA is submitted through `enp_transport_send()` to ESP-NOW.

### Node 2

- Wi-Fi initialized and connected.
- Real ESP-NOW transport initialized through `enp_context`.
- Receive callback receives a frame.
- ENP frame validation succeeds.
- Source is logical Node 1.
- Destination is logical Node 2.
- Sequence is `0x7501`.
- ACK-required flag is preserved.
- TTL is `8`.
- Payload is preserved.

## Success condition

E2-B is not considered validated merely because `esp_now_send()` returns
success. Node 2 must actually receive and validate the serialized ENP frame.

## Next step

After E2-B passes on two ESP32 nodes, freeze E2-B and proceed to E3.3.7 Phase 3
E3: connect `enp_reliability_send()` to the validated routing DATA path.
